# Property駆動開発

# TDDでProperty Based Testを使う
- 通常のUnitテストの代わりにPBTを使う
- 使う目的
    - ポジティブテスト
        - 期待した動作をするかどうか
    - ネガティブテスト
        - 期待していない動作をしないか


# Propertyの定義の流れ
- 事例から考える
    - 個々の事例ベースのテストケースを考えていた時の流れを一般化する
- Propertyの実装がテスト対象の処理と同等の複雑さを持たないように注意
    - テストが信頼できなくなってしまうため
    - 未知な入力ではなく答えを把握できる という性質を活かして実装する
